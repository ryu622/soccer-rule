# レイヤー2 vs レイヤー3の切り分け: 特徴量拡張診断

`documents/depth_sweep_results.md`・[phase3b_evolution_results.md](phase3b_evolution_results.md)
3.4.3/3.4.4節で観測した「決定木とXGBoostの差が小さい(0.08)」という結果について、
その原因を3層に分けて整理し、安価な診断実験で切り分けた。

## 1. 問題の整理(3つのレイヤー)

決定木がXGBoostに大きく劣らなかった(depth制約を外してもXGBoostに追いつかない、
差は0.08程度)という結果は、以下のどのレイヤーに起因するかが未分離だった:

- **レイヤー1**: 「LLMでルールベースを書く」がサッカーというドメインに対して筋が悪い
  → 検証しておらず、これまでの1例(1v1デュエル・9特徴量)の失敗だけで一般化はできない
- **レイヤー2**: 「1v1」という状況設定自体が、決定木で近似できる程度に単純
  → 部分的に支持されるが単独では証明できていない(決定木とXGBoostの差が小さいことは
  示唆するが、「状況が単純」なのか「表現が薄い」だけなのかを区別できていない)
- **レイヤー3**: 今回の実験条件(9特徴量というスナップショット幾何情報のみの表現)が薄い
  → これまでの一連の診断(決定木上位分岐が2〜3特徴量に集中、depth制約緩和の伸び代が
  わずか、探索範囲を分位点に直しても改善しない)から最も強く示唆されていた

レイヤー2とレイヤー3を切り分けるため、同じ1v1デュエルタスクのまま特徴量を拡張し、
決定木-XGBoostの差がどう動くかを確認する診断を実施した:
特徴量を増やしても差が変わらなければレイヤー2寄り、差が拡大すればレイヤー3寄り。

## 2. 実験条件

### 2.1 拡張した特徴量(`scripts/build_features_v2.py`、`data/tackling_features_v2.csv`)

正例・負例の抽出ロジックは`build_features.py`と完全に同一(同じ5,323行、同じ`label`)。
元の9特徴量に加えて以下4カテゴリ・7特徴量を追加した:

| カテゴリ | 特徴量 | 内容 |
|---|---|---|
| A. トレンド/加速度 | `distance_trend_1s_mps` | 直近1.0秒間の間合いの詰まり方(0.4秒版の`closing_speed_mps`より長い窓) |
| | `closing_accel_mps2` | 間合いが詰まる速さの加速度([-0.8,-0.4]区間と[-0.4,0]区間の`closing_speed`の差) |
| B. 守備者の方向転換率 | `opponent_heading_change_deg` | 守備者の進行方向ベクトルが直近0.8秒でどれだけ変化したか(方向転換しているか) |
| C. 3番目の相手・密集度 | `third_nearest_dist_m` | 3番目に近い相手選手との距離 |
| | `n_opponents_nearby_10m` | 保持者から半径10m以内にいる相手選手の数(密集度) |
| D. 直前の選択履歴 | `seconds_since_prev_event` | 直前のイベント(誰のものでも)からの経過時間 |
| | `prev_event_was_pass` | 直前のイベントがパスだったか(0/1) |

### 2.2 比較方法(`scripts/depth_sweep_v2.py`)

`documents/depth_sweep_results.md`と同じ手法(決定木のmax_depthを[3,5,8,制約なし]で振り、
XGBoostと7-fold leave-one-match-out F1を比較、`class_weight="balanced"`、
`sync_error_suspect`除外)を、(a)元の9特徴量のみ、(b)拡張16特徴量、の両方に適用して比較した。
(a)は`data/tackling_features_v2.csv`上で再計算した値であり、`depth_sweep_results.md`の数値
(F1=0.5536, 0.634)とほぼ一致することを確認済み(パイプラインの相互検証)。

## 3. 結果

| | 元9特徴量 | 拡張16特徴量 |
|---|---|---|
| 決定木ピークF1(depth振り、depth=8で頭打ち) | 0.590 | **0.591**(ほぼ不変) |
| XGBoost F1 | 0.634 | **0.660**(+0.026) |
| 決定木(depth=3)-XGBoost のF1差 | 0.080 | **0.109**(拡大) |

特徴量を増やしても決定木の性能上限は動かなかった(0.590→0.591)一方、XGBoostだけが
性能を伸ばし(+0.026)、両者の差は縮まるどころか拡大した。

### 3.1 特徴量重要度: 決定木は新特徴量をほぼ使えていない

決定木(depth=8、全データ学習)とXGBoost(全データ学習)それぞれの特徴量重要度を比較すると:

| 新特徴量 | 決定木(depth=8)の重要度 | XGBoostの重要度 |
|---|---|---|
| `distance_trend_1s_mps` | 0.039 | 0.030 |
| `closing_accel_mps2` | 0.006 | 0.033 |
| `opponent_heading_change_deg` | 0.021 | 0.027 |
| `third_nearest_dist_m` | 0.006 | 0.020 |
| **`n_opponents_nearby_10m`(密集度)** | **0.001** | **0.063**(全体5位) |
| `seconds_since_prev_event` | 0.026 | 0.036 |
| **`prev_event_was_pass`(直前イベント)** | **0.001** | **0.069**(全体4位) |

特に「周辺密集度」と「直前の選択履歴(直前がパスだったか)」は、XGBoostでは上位級の
重要度(それぞれ全体5位・4位、`carrier_speed_mps`より上位)を持つのに、決定木では
ほぼゼロ(0.001)にとどまっている。これらの特徴量には確かに予測に有用な情報が含まれているが、
単一の貪欲な木では実質的に引き出せていない、という構図が重要度からも裏付けられる。

## 4. 結論

**レイヤー2(1v1が本質的にシンプル)は棄却される。** もし1v1の意思決定が本質的にシンプルな
判断で説明できるなら、情報を追加してもXGBoostの性能は伸びないはずである。実際にはXGBoostの
F1は0.634→0.660へ伸びており、この仮説とは整合しない。

**レイヤー3(元の特徴量セットが薄かった)が支持される。** 追加した文脈情報(トレンド、
守備者の方向転換、密集度、直前の選択履歴)には決定木が使い切れていない有効な予測信号が
確かに存在し、XGBoostはそれを活用して性能を伸ばした。1対1の意思決定という状況自体が
単純というより、「その瞬間のスナップショット幾何情報だけ」を切り出した元の特徴量表現が
薄かった、と読む方が実験結果と整合する。

**レイヤー1(LLM×サッカーが筋悪い)については、依然として何も言えない。** レイヤー3が
支持された以上、これまでのLLM骨格・進化計算の不振は「特徴量表現が薄い実験条件で行った」
ことに起因する可能性が高く、「LLMでルールベースを書く」というアプローチ自体を評価する
材料にはまだなっていない。

---

## 5. 今後の検討事項

- LLM骨格・進化計算にもこの拡張16特徴量を与えて再実行すれば、決定木では使い切れなかった
  `n_opponents_nearby_10m`・`prev_event_was_pass`のような特徴量を、複合条件として
  LLMが活用できるかを直接検証できる
- TakeOn vs Pass等の別タスクへ切り替える場合も、同様に「その瞬間のスナップショット情報だけ」
  に頼った特徴量設計は同じ失敗(表現が薄いことによる性能頭打ち)を再現する可能性が高い、
  という警告として扱うべきである
